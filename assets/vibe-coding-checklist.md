## 怎么用这份清单

1. **喂给 Agent 当 rubric**：把本文件和代码库一起给它，要求逐条判断「存在 / 疑似 / 不存在」，并给出文件与行号证据。
2. **先看优先级**：A 认证、B 授权、H 接口层、N 供应链是 vibe coding 最容易批量出问题的地方，先扫这四块。
3. **不要相信「已修复」**：每条结论必须有可复现的请求或代码位置，没有证据的一律按「未验证」处理。
4. **按等级收敛**：严重项清零后再处理高危，中低危合并到技术债清单，不要平铺推进。

### 可直接复制的扫描指令

```text
你是安全审计员。附件是一份漏洞核对清单和我的代码库。

对清单中的每一条：
1. 在代码库中定位相关实现（给出 文件:行号）；
2. 判定为 存在 / 疑似 / 不存在，并说明依据；
3. 若为「存在」，写出最小复现步骤（请求示例或调用路径）；
4. 若为「不存在」，指出是哪段代码起到了防护作用。

输出格式：编号 | 结论 | 证据位置 | 复现步骤 | 修复建议
不要跳过任何条目。无法判断的写「无法判断」并说明缺什么信息。
```

## 附录 B：如果只有两小时，按这个顺序扫

1. 匿名请求遍历所有端点 → 找漏挂鉴权的接口（AUTH-01）

3. 检查前端产物里的密钥与服务角色 key（CONF-03 / CONF-04）

## 附录 C：一句话总结

Vibe coding 不会让你写不出功能，它会让你写出一个**能演示、能上线、但在第一个真实攻击者面前就崩掉**的系统——因为它的默认优化目标是「通过」，而不是「正确」和「安全」。
